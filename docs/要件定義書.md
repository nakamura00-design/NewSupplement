# NewSupplement 要件定義書

- 版: v0.2（2026-11-14 更新：試作で決まったパウチ・錠剤の仕様を反映）
- 状態: たたき台。「10. 未決事項」が決まりしだい更新する

---

## 1. 背景と目的

情報過多の時代に、人が摂取する情報は好みの分野へ偏り、社会に関する情報への関心は相対的に下がっている。NewSupplement は「日々のニュースをサプリ感覚で補う」ことで、この偏りの是正を目指す。

### このプロダクトが変えること

| | 既存のニュースアプリ | NewSupplement |
|---|---|---|
| ニュースの位置づけ | 暇なときに消費するもの | 不足を補うために摂るもの |
| 量 | 終わりがない（無限スクロール） | 1日の用量が決まっている |
| 選び方 | 好きな分野を自分で選ぶ | 不足している分野が処方される |
| 信頼性の示し方 | 記事ごとにばらばら | 全錠に成分表示がある |

単なる便利化（効率よく読める）ではなく、ニュースを読む行為の意味を「消費」から「摂取」に変えることを目的とする。そのために次の3つの制限をプロダクトの中核ルールとする。

## 2. 中核ルール（3つの制限）

以降の要件は、すべてこの3つと矛盾しないこと。

### R1. 用量制限 ― 1日3錠まで、飲んだら終わり

- 1日に出てくる錠剤は3錠（初期値）。飲み切ったらその日は追加で出ない。
- 無限スクロール、関連記事の連鎖、「もっと読む」の導線を置かない。
- 飲み切ったことが分かる完了状態を必ず見せる。

### R2. 選択制限 ― ジャンルは選ぶのではなく処方される

- 初回の診断と日々の摂取履歴から、不足している分野を割り出して配合する。
- 3錠のうち最低1錠は、ユーザーがふだん読まない分野から出す。
- ユーザーが調整できるのは配合の比率まで。特定の分野をゼロにはできない。

### R3. 中身制限 ― 成分表示できないニュースは錠剤にしない

- 出典と一次情報をたどれる記事だけを錠剤にする。
- 全錠に成分表示（分野、出典、種別、発信日）を付け、本文より先に見せる。
- 出典を確認できない記事は配信対象から外す。

## 3. 想定ユーザー

- 主対象: ニュースを読む習慣が薄い、または特定分野だけ読んでいる10代後半〜30代。
- 利用場面: 朝の支度中や通勤中など、1〜3分の短い時間。
- 求めていること: 「最低限これだけ押さえれば大丈夫」という安心と、短時間で終わること。

## 4. 用語

| 用語 | 意味 |
|---|---|
| パウチ | ホーム画面に表示されるサプリの袋。タップで開封する |
| 錠剤（ピル） | ニュース1本を包んだカプセル。タップで割れて記事が出る |
| 用量 | 1日に摂取できる錠数（初期値3） |
| 処方 | 不足分野にもとづいてその日の錠剤を決めること |
| 配合 | 処方される分野の比率 |
| 成分表示 | 錠剤ごとの分野、出典、種別（一次情報／論評）、発信日 |
| 摂取 | 錠剤を割って記事を読み終えること |

## 5. 機能要件

優先度: **M** = MVPに必須、**S** = MVP後すぐ、**C** = 将来検討

### 5.1 摂取体験

| ID | 要件 | 優先度 | 対応ルール |
|---|---|---|---|
| F-01 | ホームにパウチを表示し、タップで開封する（初回は切り口が破れ、口が開く） | M | ― |
| F-02 | 開封後、その日の用量ぶんの錠剤がパウチから出てくる | M | R1 |
| F-03 | 錠剤をタップすると割れ、成分表示 → 見出し → 要約の順に表示する | M | R3 |
| F-04 | 要約から元記事へのリンクを開ける | M | R3 |
| F-05 | 用量を飲み切ると完了状態を表示し、翌日まで新しい錠剤を出さない | M | R1 |
| F-06 | 未摂取の錠剤は翌日に持ち越さない（毎日リセット） | M | R1 |
| F-07 | 記事の末尾に関連記事やおすすめを表示しない | M | R1 |

### 5.2 処方

| ID | 要件 | 優先度 | 対応ルール |
|---|---|---|---|
| F-10 | 初回に診断（数問）を行い、初期の配合を決める | M | R2 |
| F-11 | 摂取履歴から分野ごとの摂取量を集計し、不足分野を算出する | M | R2 |
| F-12 | 毎日の3錠のうち最低1錠を不足分野から処方する | M | R2 |
| F-13 | ユーザーは配合比率を調整できるが、どの分野にも下限がある | S | R2 |
| F-14 | 処方された理由（例: 今週は国際分野が不足）を錠剤に表示する | S | R2 |
| F-15 | 週単位で分野バランスを振り返る画面を用意する | S | R2 |

分野の初期案: 政治、経済、国際、科学、地域（確定は未決事項）。

### 5.3 成分表示とコンテンツ

| ID | 要件 | 優先度 | 対応ルール |
|---|---|---|---|
| F-20 | 全錠に分野、出典（媒体名とリンク）、種別、発信日を表示する | M | R3 |
| F-21 | 出典または発信日を確認できない記事は配信対象から外す | M | R3 |
| F-22 | 一次情報と論評を区別して表示する | M | R3 |
| F-23 | 要約が自動生成の場合はその旨を表示する | M | R3 |
| F-24 | 同じ話題について複数媒体の出典を並べて示す | C | R3 |

### 5.4 アカウントと設定

| ID | 要件 | 優先度 |
|---|---|---|
| F-30 | アカウントなしで利用を始められる（履歴は端末に保存） | M |
| F-31 | アカウント登録で端末間の履歴を同期する | S |
| F-32 | 服用時刻の通知を1日1回まで設定できる | S |
| F-33 | 用量を1〜5錠の範囲で変更できる（上限あり） | C |

## 6. 体験フロー

1. アプリを開く。パウチが置かれている。
2. パウチをタップ。切り口が破れ、口が開き、傾いて3錠が転がり出る。
3. 錠剤をタップ。割れて成分表示が出る。続いて見出しと要約を読む。
4. 2錠目、3錠目も同様に摂取する。
5. 3錠目を読み終えると完了状態になり、その日は新しい錠剤が出なくなる。
6. 翌日、新しい3錠が処方される。

## 7. ビジュアルとアニメーションの要件

### 7.1 ブランド

- ロゴ: 透明なガラス質感のカプセルに NewSupplement の文字。
- 透明感は情報源の透明性を、淡い青と白は日本のニュースらしい清潔感と新鮮さを、カプセル形は「不足を補う」意図を表す。
- 基調色: ロゴの青（濃い青から水色への階調）、白、淡い青の背景。

### 7.2 パウチ

**形と質感**

- 四辺を熱シールした平袋。外周の約1cm（袋幅の約8.5%）は平らにプレスされ、内側だけが枕のように膨らむ。
- 上部にチャック、切り口（左右の丸い切り欠き）、吊り下げ穴を持つ。
- 光と影は絵柄に描き込まず、立体の形と照明から出す。絵柄はこの形に貼り付ける。
- 照明で印刷の色が白飛びしないよう、絵柄の発色を保つ。
- 開封時に切り口が破れ、口がレンズ状に開く。

**表面の構成**

- 中央の帯にロゴ（ガラスのカプセル）を大きく置く。ロゴが商品名を兼ねるため、別の商品名は置かない。
- 上段：欧文の小見出し「DAILY NEWS SUPPLEMENT」と、コピー「「ついニュース読むの忘れちゃう...」「SNSばかり見てしまった...」そんなお悩みに。」。中央揃えで、引用2行を小さく、締めの1行を大きく置く。
- 帯の右上に「1日3錠」の丸いシール。
- 下段：5分野のチップ（分野色の点つき）、内容量と目安量、「成分表示つき」、注記（出典を確認できない記事は配合しない／3錠のうち1錠はふだん読まない分野から処方）。
- 裏面：成分表示（分野、出典、種別、発信日、目安量）。

**4案**

| 案 | 内容 |
|---|---|
| 全面ブルー | 全面がロゴの青の階調（現時点の完成案） |
| 上ブルー・下ラベンダー | 下半分が青みがかった薄い紫 |
| シルバー縁 | ネイビー地にサテン調のシルバー箔の縁と二重枠 |
| ゴールド縁 | ネイビー地にシャンパン寄りのゴールド箔の縁と二重枠 |

- 箔は鏡面の強い縞ではなく、明暗差の小さいサテン調にして全体と調和させる。
- 既存商品のデザインは流用せず、構成と質感だけを参考にする。

### 7.3 錠剤

- 片側が透明、片側が色付きのカプセル。ロゴと同じく透明度が高く、ゼリーやオイルが詰まったような質感にする。
- 色付きの側は分野ごとに5色。

| 分野 | 色 |
|---|---|
| 政治 | 青（先端に向かって紫） |
| 経済 | 緑 |
| 国際 | オレンジ |
| 科学 | 紫 |
| 地域 | ピンク |

- 落下、転がり、衝突で重さが感じられること（物理演算、衝突音、接地影）。
- タップするとすぐ2つに割れ、それぞれが自然に転がる。三角の破片（1錠あたり14個）が散り、小さな白い光とガラスの割れる音が出る。
- 破片の色は白、その錠の色の淡色、淡色の紫寄りの3色からランダム。
- 割れたあとにニュースカードを表示する。カードはアニメーションさせない。
- ロゴの見た目（多重屈折、床への集光）はリアルタイム描画では完全には再現できない。近似で寄せる。

### 7.4 実装方式

- パウチと錠剤はリアルタイム3D（WebGL）で描画する。ガラスの屈折と映り込みは転がるたびに変化するため、2Dの絵や動画では再現できない。
- 記事、成分表示、設定などの画面は通常の2D UIで作る。
- 用量が3錠なので同時に描画する錠剤は少なく、スマートフォンでも負荷を抑えられる。
- 3Dを表示できない端末と「視差効果を減らす」設定の利用者には、静止画と簡易アニメーションで同じ体験を提供する。
- 描画は Three.js（r134）、物理演算は cannon.js（0.6.2）を使う。

試作: 「NewSupplement パウチとピルの試作 v2」（アーティファクト）、リポジトリの `index.html`。

## 8. 非機能要件

| 項目 | 要件 |
|---|---|
| 対応環境 | スマートフォンのブラウザを最優先。続いてPCブラウザ、ネイティブアプリ |
| 性能 | 開封から錠剤が止まるまで60fpsを目標、中位機種で30fpsを下回らない |
| 起動 | 初回表示からパウチを操作できるまで3秒以内（4G回線） |
| アクセシビリティ | アニメーションなしでも全機能を使える。読み上げに対応。文字と背景のコントラストを確保 |
| 所要時間 | 1日ぶんの摂取が3分以内で終わる長さに要約を収める |
| プライバシー | 摂取履歴は処方のためだけに使い、広告配信に使わない |
| 中立性 | 処方ロジックは分野の偏りだけを是正し、特定の論調へ誘導しない |

## 9. コンテンツとデータ

- 記事データの最小項目: 見出し、要約、分野、媒体名、元記事URL、種別、発信日時。
- 摂取履歴の最小項目: 日付、錠剤ID、分野、摂取の完了有無。
- 記事の取得元と利用許諾の方法は未決（10章）。見出しと要約の扱いは各媒体の利用条件に従う。

## 10. 未決事項

| # | 事項 | 決めること |
|---|---|---|
| 1 | ニュースの取得元 | 提携、公式API、RSSのどれを使うか。要約の作成方法と許諾 |
| 2 | 分野の定義 | 5分野でよいか。分野の判定を誰が（何が）行うか |
| 3 | 不足の算出方法 | 診断の設問、履歴の集計期間、下限の比率 |
| 4 | 種別の判定 | 一次情報／論評を誰が判定するか |
| 5 | 用量 | 3錠固定か、範囲内で変更可か |
| 6 | 開発方式 | Webを先に作りアプリは後か。3Dをアプリでどう表示するか |
| 7 | パウチのデザイン | 4案から1つに絞るか、分野や曜日で使い分けるか（全面ブルーは完成案） |
| 8 | 収益モデル | 広告を入れない前提でどう運営するか |
| 9 | 分野と色の対応 | 5色の割り当てを確定するか |

## 11. 成功の指標（案）

- 完了率: 開封した日のうち、3錠を飲み切った日の割合。
- 分野バランス: ユーザーごとの週あたり摂取分野数。利用開始前後の変化。
- 継続: 週3日以上摂取したユーザーの割合。
- 滞在時間は指標にしない（R1と矛盾するため）。

## 12. 進め方

1. 試作でパウチと錠剤の見た目・動きを確定する（現在）
2. 摂取フロー（F-01〜F-07）と成分表示（F-20〜F-23）を固定データで実装する
3. 診断と処方（F-10〜F-12）を実装する
4. ニュース取得元を接続し、少人数で試用する
